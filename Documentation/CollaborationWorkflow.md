# DEAD LETTER 협업 및 맵 전달 규칙

## 핵심 원칙

한 사람이 작업 중인 `.unity` 씬을 다른 사람이 동시에 수정하지 않습니다. Unity 씬은 텍스트 형식이지만 GameObject와 GUID 변경이 많아 충돌을 사람이 직접 해결하기 어렵습니다.

## 친구가 맵을 만드는 순서

1. GitHub에서 프로젝트를 복제합니다.
2. Unity **6000.0.58f2**로 프로젝트를 엽니다.
3. `main`에서 `level/맵이름` 브랜치를 만듭니다.
4. 맵은 `Assets/_Project/Scenes/Maps/Incoming`에 새 씬으로 만듭니다.
5. 환경 프리팹은 `Assets/_Project/Prefabs/Environment`에 저장합니다.
6. 모델과 텍스처는 `Assets/_Project/Art`에 저장합니다.
7. `.meta` 파일을 포함해 커밋하고 브랜치를 푸시합니다.
8. 맵이 준비되면 해당 브랜치 또는 Pull Request 주소를 전달합니다.

## 파일로 전달해야 하는 경우

`.unity` 파일만 보내면 안 됩니다. Unity에서 `Assets > Export Package`를 선택하고 **Include Dependencies**를 활성화한 `.unitypackage`로 전달합니다.

받은 패키지는 현재 작업 브랜치에 바로 임포트하지 않고 별도 검수 브랜치에서 먼저 확인합니다.

## 담당 영역

| 영역 | 맵 제작자 | 프로젝트 담당자 |
| --- | --- | --- |
| 공간 배치, 벽, 바닥, 천장 | 작업 | 검수 |
| 환경 모델, 텍스처, 머티리얼 | 작업 | 최적화 검수 |
| 조명 기본 배치 | 작업 | 분위기 및 성능 검수 |
| Player, 입력, UI | 수정하지 않음 | 작업 |
| 문과 업무 상호작용 코드 | 수정하지 않음 | 작업 |
| Build Settings | 수정하지 않음 | 관리 |

## 통합 체크리스트

- Missing Script, Missing Material, 분홍색 머티리얼이 없는가
- 모든 모델, 텍스처, 프리팹과 `.meta` 파일이 포함됐는가
- URP 머티리얼로 정상 출력되는가
- 벽, 바닥, 문에 필요한 Collider가 있는가
- 플레이어가 문과 가구에 끼지 않는가
- Player 스폰 위치와 카메라 높이가 정상인가
- 문, 컴퓨터, 편지 등 상호작용 위치가 명확한가
- 조명이 너무 어둡거나 과도하게 밝지 않은가
- 씬이 친구의 개인 경로나 외부 패키지에 의존하지 않는가

## 현재 맵 생성 도구

`Tools > DEAD LETTER > Generate Graybox Map`은 수동 테스트 도구입니다. 에디터 시작 시 자동 실행되지 않으므로 전달받은 맵을 임의로 덮어쓰지 않습니다.
