# DEAD LETTER 맵·배치 수정 인계 문서

빌드 파일(`level1`, `sharedassets1.assets`)을 직접 고쳐서 확인한 내용을 유니티 프로젝트로 옮기기 위한 문서입니다.
빌드에서 고친 것은 프로젝트에서 다시 빌드하면 사라지므로, 아래 내용을 프로젝트 씬에 적용해야 합니다.

## 이 폴더에 있는 것

| 파일 | 내용 |
|---|---|
| `scene_changes.json` | 원본 빌드와 최종 빌드를 비교해 뽑은 전체 변경값 (Transform, 활성 상태, 렌더러, 콜라이더, 스크립트) |
| `textures/` | 방 텍스처 6장, 소품 텍스처 5장, 문 텍스처 1장 |
| `맵_최신.fbx` | 최신 맵 FBX (복도 끝·창구 정점 일부와 탕비실 위치가 이전 FBX와 다름) |

## 목표 배치

- 남쪽 창구, 북쪽 작업실, 동쪽 창고, 서쪽 탕비실, 북서쪽 히든룸 (히든룸 문은 북쪽 복도의 서쪽 벽)
- 맵 FBX는 원래 좌표에서 Y축 180° 회전 + 복도 중심을 원점에 맞춘 상태
- 원본 씬은 북쪽이 창고, 동쪽이 작업실이었음. 두 방의 게임 오브젝트를 서로 옮겼음

## 변경 내용 요약

1. **맵 외피** (`Final Map Visuals (Visual Only)` 아래 복도/비밀의방/탕비실/창구/창고/작업실): 각 자식의 로컬 위치·회전 변경. 루트는 그대로.
2. **히든룸**: 문(기둥 2개, 피벗)을 Z로 -0.124 이동. 충돌 벽·바닥·천장을 북쪽으로 확장.
3. **소품** (`Production Room Art`): 래퍼(`X Production Art`, `X Art Content`, `Size - X`, `Storage Shelf Set`)의 Transform을 전부 초기값(위치 0, 회전 0, 스케일 1)으로 되돌리고, 실제 메시 오브젝트만 균등 스케일로 배치. 원본은 축마다 다른 스케일이 걸려 모델이 늘어나고 비틀려 있었음.
4. **소품 크기**: FBX 원본 크기에 균등 배율 적용. 창구 책상 0.67, 작업실 책상 0.50, 컨베이어 0.85, 창고 선반 0.85, 탕비실 탁자 0.75, 소파 0.70, 냉장고 0.70, 탕비실 선반 0.85, 히든룸 책상 0.60, 시계 0.60, 액자 1.35. 책상 위 소품은 책상과 같은 변환을 공유.
5. **창고 선반 충돌**: `Collider - 칭고`의 `ArtColliderFollower`가 런타임에 콜라이더를 선반 전체(ㄷ자 안쪽 포함) 크기로 키워서 방에 못 들어가는 버그가 있었음. 이 컴포넌트를 끄고 대상을 비움. 대신 비활성 그레이박스 `Storage West/East/Rear Shelves`를 켜고 자식 MeshRenderer만 꺼서 선반 줄별 충돌로 사용.
6. **게임 오브젝트 이동**: 작업실 것(포장대, 도장 6개, 포장 상자, 컨베이어 단말기, 우편함)은 북쪽 방으로, 창고 것(빈 상자 5개, 숙취해소제, 안전모, 절연장갑, 교복)은 동쪽 방 선반 위로. 방 조명 2개도 교체. 창구 아이템 3개는 책상 상판 위로.
7. **안 쓰는 문 제거**: `Storage Exterior Door` 피벗 비활성, 기둥·상인방 렌더러 끔. 왼쪽 기둥을 넓혀 구멍을 충돌로 막음.
8. **문 모델**: 작동하는 문 6개의 피벗 아래에 FBX 문 모델을 자식으로 넣고, 기존 그레이박스 문짝·패널·손잡이·경첩 핀은 렌더러만 끔(콜라이더 유지).
9. **텍스처**: 아래 표 참고.

## 프로젝트에 옮길 때 주의할 점

- **씬 생성 스크립트 확인**: 씬에 `Reference Layout Marker - Compact Textured Rooms v14` 같은 오브젝트가 있는 것으로 보아 그레이박스를 에디터 스크립트가 생성했을 수 있습니다. 그렇다면 씬을 직접 고치지 말고 생성 스크립트의 값을 고쳐야 다시 생성할 때 덮어써지지 않습니다.
- **`ArtColliderFollower`**: 나머지 소품 콜라이더는 이 스크립트가 메시 크기를 따라가므로 메시 Transform만 맞으면 됩니다. JSON의 `boxColliders` 값은 참고용입니다. `Collider - 칭고`만 예외로 꺼야 합니다.
- **문 모델 부착**: 빌드에서는 구조상 장식 패널 하나와 자리를 맞바꾸는 식으로 넣었습니다. 프로젝트에서는 FBX 문 오브젝트를 해당 피벗의 자식으로 옮기기만 하면 됩니다. JSON의 문 모델 `localPosition/Rotation/Scale`은 피벗 기준 값입니다.
- **맵 FBX 교체**: `맵_최신.fbx`로 기존 맵 FBX를 덮어쓰면 됩니다. UV와 재질 구성은 이전과 같습니다.
- **정적 배칭**: 창구·창고·작업실 외피는 빌드에서 정적 배칭되어 있었습니다. 프로젝트에서는 Transform만 바꾸면 됩니다.
- **오브젝트 이름**: 북쪽 문이 `Storage Hall Door`, 동쪽 문이 `Workshop Hall Door`로 방과 이름이 엇갈려 있습니다. 동작에는 영향이 없지만 정리하려면 이름과 참조를 같이 바꿔야 합니다.
- **미검증**: 이 변경은 씬 데이터 분석(평면도, 이동 가능 영역 계산)으로만 확인했고 게임 실행 테스트는 하지 못했습니다. 적용 후 각 방 진입, 문 6개 개폐, 창고 아이템 줍기, 작업실 포장·컨베이어, 손님 응대를 직접 확인해야 합니다.

## 아직 안 된 것

- 손님 캐릭터 5명(직장인=음주운전, 학생=모범생, 노동자=부실공사, 익사자=불량이, 인형탈=마스코트 맨) 모델·움직임·날짜별 텍스처. 사람형 4명은 유니티 휴머노이드 뼈대이고 애니메이션 클립이 없음. 인형탈은 Biped 뼈대에 클립 1개 있음.
- 문틀(기둥·상인방)은 그레이박스 그대로.

## 코덱스에게 줄 지시문

아래를 그대로 붙여 넣고, 이 폴더를 프로젝트 저장소 안(예: `Docs/handoff/`)에 넣어 두세요.

```
Docs/handoff/ 폴더의 HANDOFF.md와 scene_changes.json을 읽고, 게임플레이 씬(빌드 인덱스 1)에 그 변경을 적용해줘.

규칙:
1. 먼저 그레이박스나 소품 배치를 생성하는 에디터 스크립트가 있는지 찾아. 있으면 씬을 직접 고치지 말고 그 스크립트의 값을 고쳐. 없으면 씬을 고치는 일회용 에디터 스크립트(Assets/Editor/ApplyHandoff.cs)를 만들어서 적용해.
2. scene_changes.json의 path는 씬 계층 경로야. transforms는 newParentPath가 있으면 먼저 부모를 옮기고, 그다음 localPosition, localRotationQuat_xyzw, localScale을 그대로 넣어. active, renderers, scripts 항목도 그대로 적용해. boxColliders는 "Collider - 칭고"만 적용하고 나머지는 ArtColliderFollower가 처리하게 둬.
3. path를 못 찾는 항목이 있으면 건너뛰지 말고 목록으로 보고해. 추측해서 다른 오브젝트에 적용하지 마.
4. 맵 FBX를 Docs/handoff/맵_최신.fbx로 교체하고, textures 폴더의 PNG를 임포트해서 HANDOFF.md의 "텍스처 연결" 표대로 재질에 연결해. 표에 있는 재질의 Base Color는 흰색으로.
5. HANDOFF.md에 없는 스크립트, UI, 게임 로직은 건드리지 마.
6. 끝나면 적용한 항목 수, 못 찾은 항목, 직접 판단한 부분을 정리해서 알려줘. 플레이 테스트는 내가 할 테니 "미검증" 항목의 확인 순서도 같이 적어줘.
```
